# October 2026 field-test archive

This archive preserves the complete useful contents of the former
`scratch/field-testing` folders, including files previously hidden by an ignore-all
rule. Raw recordings and saved results were copied byte for byte. Only Python
scripts with machine-specific paths were adapted; `source-manifest.json` records
the original hashes and the adapted hashes where applicable.

| Collection | IGC files | Contents |
|---|---:|---|
| `2026-10-25-firmware-0.2.4-968` | 266 | Device downloads by hardware/device, additional tracks under `unknown hardware`, logbooks, diagnostic evidence, motion analysis |
| `2026-10-27` | 59 | Device downloads, logbooks before and after repair, start/stop threshold analysis and C++ replay variants |

These are download/collection dates. Some recordings predate the collection, and
some downloads overlap. Keep the device hierarchy and duplicate filenames: they
preserve the context of each device download. Logbook `.bak` and `.tmp` files are
retained as evidence of save and repair behavior. Python bytecode, plotting caches,
and the obsolete ignore-all rule are excluded. `.gitattributes` disables line-ending
conversion in this archive so Git preserves the hashed evidence on every platform.

## Verify preservation

From the repository root, using Python 3.10 or newer:

```sh
python test-data/field-testing/verify_archive.py
```

The verifier checks every archived source file and the historical replay input
against its SHA-256 hash, including all 325 IGC files. It also checks Python syntax.

## Reuse the scripts

The scripts write outputs beside themselves. Copy this whole folder to a working
directory before rerunning them so the checked-in evidence stays unchanged. Keep
both collection folders together because the later analyses reuse the earlier
parser and recordings. Python packages required by the analyses are listed in
`requirements.txt`; the archive verifier needs only the standard library.

For example, from the repository root:

```sh
python -m pip install -r test-data/field-testing/requirements.txt
python -c "import shutil; shutil.copytree('test-data/field-testing', '.pio/field-analysis')"
python .pio/field-analysis/2026-10-25-firmware-0.2.4-968/_motion-analysis/analyze.py
python .pio/field-analysis/2026-10-25-firmware-0.2.4-968/_motion-analysis/features.py
python .pio/field-analysis/2026-10-27/_analysis/analyze.py
```

The October 25 follow-ups (`sweep.py`, `blended_analysis.py`, `fast_windows.py`,
`forward_analysis.py`, `thermal_analysis.py`, `stop_refinement.py`, and
`check_stop_proposals.py`) consume the saved/generated JSON beside them.
`publish_analysis.py` rebuilds the HTML reports locally.

The October 27 `verify_variants.py` uses the archived baseline header and
`historical-replay-input.txt`, rather than an old worktree or `.pio` directory.
It prepares variant headers and `combined-input.txt`. To evaluate the baseline
against those inputs with a host C++17 compiler, from that copied `_analysis`
directory:

```sh
python verify_variants.py
g++ -std=c++17 -O2 -I variants/baseline replay.cpp -o replay
./replay < combined-input.txt > variant-baseline.csv
```

Use the corresponding include directory for each other variant. To recreate the
October 27 standalone replay output, feed `replay-input.txt` to the same executable
and save its output as `replay-results.csv`. `summarize.py`, `stop_bounds.py`, and
`threshold_sweep.py` consume that output; `report.py` renders plots and the initial
report. `earlier_stop_sweep.py` also uses October 25 data. `comparison_report.py`
reads the archived `variant-*.csv` files to compare the experimental settings.
Not every historical header variant was generated by `verify_variants.py`; the
saved snapshots and outputs are retained for those manual experiments as well.
